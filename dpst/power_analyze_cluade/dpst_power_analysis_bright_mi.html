「关闭」这段测试期间 CPU 平均使用率高达 17.7%（GPU 也有渲染负载），而「开启」这段几乎完全空闲（1.5%）—— 说明两次测试时后台很可能各自运行了不同的程序/任务，并非同一 workload 下单独切换 DPST 开关。 下文中 CPU 封装功率 −38.6% 这类差异，主要反映的是两段测试的系统负载差异，而不是 DPST 本身的算法开销变化； 与之相关的「整机功耗」「屏幕/背光估算」也会被这部分无关负载污染，实际数值可能被高估。

建议：重新采集一组明亮图片数据，测试时确保开启/关闭两段除 DPST 状态外，其余负载（CPU/GPU 使用率、后台程序）保持一致，才能得到可信的对比结论。以下数据仅供参考。

方向上符合预期：明亮画面本身需要较高背光才能正常显示，DPST 通过降低背光 + 提升局部对比度来省电的空间远小于暗图场景， 因此背光节省幅度（估算 −2.2%）明显小于暗图（−18.5%）。但由于本次明亮图片测试存在负载污染问题，−2.2% 这个具体数字的置信度较低， 真实的 DPST 背光节省效果需要在负载可控的重新测试中确认。

六、方法与结论

  • 平稳段截取 + IQR 过滤方法与暗图报告一致：先剔除开头热身段，再对剩余数据做 1.5×IQR 异常值过滤后取均值。
  • 数据集依然没有独立的背光/面板功率传感器，"屏幕/背光功耗"仍为「整机功耗 − CPU 封装功率」的推算值。
  • 本次明亮图片测试最大的问题是两段日志系统负载不一致（CPU 使用率 17.7% vs 1.5%，GPU 使用率 5.5%/2.8% vs 0%），使 CPU 封装功率、整机功耗的对比混入了与 DPST 无关的负载变化，不能视为 DPST 的真实节能效果。
  • 「系统总功率 [W]」（PSys 域）在本平台数据中依然存在小于 CPU 封装功率的异常，未采用该列代表整机功耗。
  • 建议：重新采集明亮图片场景数据，测试时保持关闭/开启两段的后台任务、CPU/GPU 负载一致（如测试前关闭无关程序、只在切换 DPST 开关前后各静置观察），才能得到可与暗图场景直接比较的、可信的背光节能结论。
