DPST 开启 / 关闭 功耗对比分析 · Huawei PC

数据来源：huawei_pc/ 下 dpst_{disable,enable}_{dark,bright}.CSV · HWiNFO 传感器日志 · 方法：热身段截取 + CPU 负载净化 + 1.5×IQR 异常值过滤

⚠ 本次数据新增问题：部分日志中段/尾段混入无关后台负载 已处理

与之前两份报告不同，这批日志里「不稳定」不只出现在开头：dpst_disable_dark.CSV 从第 25 个点（热身结束）之后， 约 59% 的时间里 CPU 使用率持续在 13~27% 区间反复波动（对照组 dpst_enable_dark.CSV 同期几乎全程 2~4% 空闲）， dpst_disable_bright.CSV 也在最后约 230 个点出现同样特征的负载。这类周期性 CPU 占用与 DPST 开关无关（很可能是后台程序/扫描任务）， 如果不剔除会严重高估「关闭」侧的功耗，从而虚增 DPST 的节能效果。因此本次分析在原有方法基础上新增了一步：按 CPU 总使用率 < 6% 过滤，只保留系统空闲的采样点，再做 IQR 异常值过滤。

一、数据处理方法（三步走）

  1. ① 热身段截取：按放电功率时间序列，丢弃每份日志开头功耗衰减/波动的热身段。
  2. ② CPU 负载净化（本次新增）：热身段之后，只保留 CPU 总使用率 < 6% 的采样点，剔除与 DPST 无关的后台负载区间。
  3. ③ IQR 异常值过滤：对净化后的数据做 1.5×IQR 过滤，剔除零星瞬时尖峰，再取均值。

七、方法与注意事项

  • 三步清洗：热身段截取 → CPU 使用率 < 6% 的负载净化（本次数据新增，用于剔除与 DPST 无关的后台任务区间）→ 1.5×IQR 异常值过滤，最终对净化后的稳态数据取均值。
  • "屏幕/背光功耗"仍为推算值 = 整机功耗（电池放电绝对值）− CPU 封装功率；本机额外有「系统总功率」（PSys）可交叉验证，两者结论方向一致。
  • "暗色·关闭"日志因负载污染严重，净化后仅保留 40.6% 的采样点（约 8.8 分钟），但仍有足够样本支撑均值估计。
  • 结论与此前两份报告（vs_workspace 根目录暗图 / bright 文件夹）方向一致：DPST 对 CPU 负载影响可忽略，节能主要来自背光侧；暗色场景节能远大于明亮场景。三台设备/三批数据相互印证，增强了该结论的可信度。
